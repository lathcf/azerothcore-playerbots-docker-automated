## The rule this table exists to execute

Every era predicate in `mod-era-talents`' reconcile/pin C++ currently encodes **"high era ==
native."** Concretely: most of the module's era-branching code is written as either a bare
`era == ERA_VANILLA` / `era != ERA_VANILLA` two-way split, or (in a few places) an
`era >= ERA_TBC` two-way split that lumps TBC in with WotLK as "the native side." That collapse
is **permanently correct for WotLK** (WotLK is native forever) and **correct for TBC only while
TBC stays gated native** — i.e. only until `EraHasTalentTrees` (currently Vanilla-only,
`modules/mod-era-talents/src/EraTalentIP.cpp`) is extended to also return `true` for
`ERA_TBC`, which happens once all nine TBC classes are authored and real-client verified.

**Phase 0 changes NO reconcile/pin code.** During the whole TBC buildout the existing
`era >= ERA_TBC` / `era != ERA_VANILLA` force-grant and strip paths remain correct AS WRITTEN,
because TBC characters are still native (they never enter the era-managed branch). The actual
code flip — splitting each collapsed `era >= ERA_TBC` / `era != ERA_VANILLA` predicate into
explicit `ERA_TBC` / `ERA_WOTLK` arms with per-class tree-aware handling — lands as **ONE
"final enablement" task**, executed AFTER all nine TBC classes ship. This table's job is to
enumerate every era-predicated site ahead of time and tag its disposition, so that final task
is mechanical: walk the table and read each row's own **Disposition** column — that column, not
the tag alone, is the authoritative source for whether a row needs action. The tag is a quick
filter (e.g. grep `TBC->{class}` for one class's open questions), but a `DECIDED` row can still
prescribe the mechanical `era>=ERA_TBC` → explicit-arm split (see the DECIDED legend entry
below); only `WOTLK-PERM` and `VANILLA-PERM` rows are guaranteed to need no touch at all.

## Tag legend

| Tag | Meaning |
|---|---|
| **WOTLK-PERM** | Permanently correct as-is. The predicate means "native high era," and WotLK is native forever — never touch this row at final enablement. |
| **VANILLA-PERM** | A permanent Vanilla-only behavior (forever gated to `era == ERA_VANILLA`), independent of whether TBC or WotLK is native. |
| **TBC->{class}** | Content-dependent. That class's TBC authoring phase decides the disposition when its trees exist — the Disposition column states the concrete open question that phase must answer. |
| **DECIDED** | Resolved now, in the Phase-0 brainstorm — no further decision needed at final enablement (may still require the mechanical `era>=ERA_TBC` → explicit-arm code split, but the CONTENT decision is already made). |
| **FINAL-ENABLEMENT** | The predicate is fine as-is during the whole buildout; it must be rewritten into its three-way form as part of the single final-enablement task (e.g. the `.eratalents doctor` orphan checks that would false-positive on legitimate TBC era spells once TBC is managed). |
| **DECIDED-DEFER** | The Phase-0 decision is to defer the actual authoring to a specific class phase (e.g. patch-0018 Shatter: the Vanilla marker stays Vanilla-only now; whether TBC's real Shatter talent reuses the core patch is a mage-phase call). |

A row tagged `TBC->{class}` never gets a guessed WOTLK-PERM/DECIDED disposition — if the code's
correct behavior once that class's TBC trees exist isn't obvious from reading it today, the tag
stays `TBC->{class}` and the Disposition column states the open question instead.

## Note on scope: bare `EraFromIP(p)`/`EraHasTalentTrees(era)` call sites are excluded

The Step-1 greps also match plain era-resolution call sites with no era-VALUE branching —
e.g. `EraTalentPin.cpp:64` (`EraId now = EraFromIP(p);`), `:138`, `:144`
(`EraHasTalentTrees(EraFromIP(p))`), `:197`, `:222`. These aren't predicates that encode a
Vanilla/TBC/WotLK split; they're the generic, already-era-agnostic resolution path (or the
`EraHasTalentTrees` allowlist gate itself, which needs no per-class change — it's edited exactly
once, centrally, when TBC's `EraHasTalentTrees` flips to `true`). They are intentionally NOT
given their own table rows.
